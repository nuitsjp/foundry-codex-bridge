# Sync はロールバックせず再実行で収束させる

## Context

Sync は Provider 更新、API key 登録、カスタムモデル調整、selected model 更新、Codex catalog sync、実接続テストという複数の公開 `ocx` CLI 操作で構成される。opencodex はこれらを一括処理するトランザクション API を提供していない。Bridge が設定のスナップショットと独自ロールバックを実装すると、opencodex の内部形式への依存と、並行して行われた利用者の変更を失う危険が増える。

## Decision

Bridge は Sync を再実行可能な収束処理として実装する。各段階で現在状態を取得して必要な差分だけを適用し、途中失敗時は完了済み操作を巻き戻さない。GUI は段階ごとの成功・失敗を表示し、次回 Sync は現在状態を読み直して不一致を修復する。同一アプリ内では複数の Sync を並行実行しない。

## Consequences

失敗直後には Provider だけが存在するなどの部分状態が残り得るが、次回 Sync で修復できる。Bridge は opencodex の設定ファイルを直接読んだり復元したりせず、公開 CLI の契約内に留まる。処理結果は単一の成否ではなく、段階別に利用者へ示す必要がある。
